# agevault 升级说明

维护记录：正式版为 [v1.2.0](https://github.com/ly88321/agevault/releases/tag/v1.2.0)，标签固定指向提交 `92231f37f17a9a9b346944d792c47c8861b6e1c1`。发布前的 15 项检查和七个公开附件均已验证；[正式发布任务记录](https://github.com/ly88321/agevault/actions/runs/39554275019)保留供审计。下面保留当时确认的版本说明；后续文档和维护提交不改变该版本或附件。

本次升级引入混合后量子密钥和多接收者共享，同时保留 Fork 原有的流式加密、分块擦除、原子写入、自定义密钥路径及旧格式兼容能力，并加强数据恢复与解包安全。

## 后量子加密

- 支持通过 `-pq` 生成 **X25519 + ML-KEM-768 混合后量子密钥**。
- 保留传统 X25519 密钥支持，可继续使用已有密钥。
- 混合方案结合传统与后量子算法，为长期保存的数据提供面向量子计算威胁的保护。

## 多接收者共享

- 同一份密文可授权给多个接收者，每位接收者使用自己的私钥解密，无需共享私钥。
- 加强接收者列表与所选密钥的一致性验证，避免错误密钥或过期元数据导致无法恢复。
- 使用后量子密钥共享时，应确认所有接收者的客户端均支持相应格式。

## 旧版兼容

- 继续支持旧版 ZIP 和 tar 归档，以及历史密钥命名与元数据格式。
- 保留自定义密钥路径，并修复旧版外部密钥缺少元数据时的迁移问题。
- 显式指定的有效密钥优先于过期元数据；加密前会检查密钥是否位于待擦除目录中。
- 保留 POSIX 平台合法的历史文件名，同时对 Windows 特殊路径和设备名称实施限制。

## 可选保留密文

解锁时可选择保留原始加密归档：

```text
agevault documents unlock --key alice.age --keep-ciphertext
```

- 完整验证并恢复目录后，保留加密归档，密文字节保持不变。
- 不使用该选项时，成功解锁后仍按默认行为清理密文。
- 保留的密文会阻止再次加锁覆盖；重新加锁前，请核对恢复的数据，并将原密文移至备份位置。

## 安全与故障恢复

- 解锁时验证完整加密数据流，在私有暂存目录中完成解包和校验，再发布恢复后的目录。
- 拒绝越界路径、符号链接、特殊文件、重复条目和不符合预期的归档根目录。
- 加密归档完成同步和原子发布后，才开始擦除原始目录。
- 加强磁盘写入不足、短写入、同步失败、关闭失败及文件发布失败的错误处理。
- 清理失败会提供更明确的恢复提示，区分“恢复未完成”和“目录已恢复但密文清理失败”。

新增回归测试覆盖磁盘空间不足、I/O 故障、部分写入、同步和重命名失败，以及 15 个关键阶段的进程突然终止。断电模型验证未持久化的数据和目录记录丢失时的恢复顺序。

## 验证结果

合并到 main 的提交 `709d499` 已通过全部 **7 项 CI 检查**：

- Linux、Windows 的双 Go 版本测试；
- macOS Intel 与 ARM 测试；
- Nix 检查。

测试同时覆盖旧版归档、传统及混合密钥共享、损坏和截断密文、路径安全、故障恢复与 64 MiB 流式往返处理。

## 已知限制

- **断电测试属于软件模型与进程中断测试**，不能替代真实硬件断电或故障磁盘验证；实际持久性仍取决于文件系统、设备和控制器缓存。Windows 的目录持久化保证也未由这些测试建立。
- 进程崩溃或清理失败可能留下含明文的暂存目录。建议配合全盘加密使用，并按照错误提示处理残留文件。
- 成功恢复目录后，若密文擦除中途失败，可能留下已损坏的加密归档；此时应优先核对并备份已恢复的数据。
- 分块覆盖无法保证彻底清除 SSD、写时复制文件系统、快照或备份中的历史数据。
- 旧版 ZIP 解锁仍可能需要与归档大小相当的内存。
- 原子发布依赖文件系统的硬链接支持；不支持的环境可能无法完成加密。
- 不支持操作过程中由其他进程恶意并发修改源目录。
- 旧客户端不一定能够读取新生成的后量子密钥或密文；跨平台恢复也可能受目标系统文件名规则限制。
- 接收者公钥的真实性需要通过可信渠道确认；多接收者共享不提供对既有密文副本的追溯撤销。
- 本次安全审查与自动化测试不等同于独立密码学审计，也不能替代可靠备份。
